# 폰트 시스템 (PGF·GTF)

## 구성

`ui/out_game`의 FPK들에 PGF+GTF 쌍으로 수록. 4종:

| 폰트 | 텍스처(GTF) | 용도 | 한글화 |
|---|---|---|---|
| default | 352×4096 | 메인 본문 | O |
| nakamaru16 | 240×4096 | 보조 본문 | O |
| nakamaru14 | 16×4096 | 소형(302자, 한자 없음) | 원본 유지 |
| sogei | 32×4096 | 소형(302자, 한자 없음) | 원본 유지 |

7개 FPK(ingame, mapmode, outgame_mcnsel/result/talk/test/title)에 폰트가 중복
수록되어 있어 전부 교체해야 한다.

## GTF (글리프 아틀라스)

표준 PS3 GTF. 헤더 0x80 + 8bpp 선형 픽셀. default는 `fmt=0xA1`(B8, linear),
`352×4096`, `pitch=352`. 텍스처 데이터는 `+0x80`부터.

> **주의**: 아틀라스를 원본과 같은 크기로 유지하면 헤더를 손댈 이유가 없다.
> 헤더의 텍스처-데이터 오프셋 필드를 잘못 쓰면 게임이 엉뚱한 위치를 읽어 화면
> 전체가 세로 줄무늬로 깨진다(실제로 겪은 버그). 크기 유지 시 원본 헤더를 그대로 복사.

## PGF (글리프 테이블)

표준 PGF가 아닌 커스텀 포맷.

```
32바이트 헤더:
  +0x04 u16 first_code      첫 글자 UCS2
  +0x06 u16 glyph_count
  +0x10 u16 tex_width
16바이트 글리프 레코드 × count (UCS2 오름차순 정렬):
  u32 code    UTF-8 바이트열을 BE 정수로
  u16 ucs2
  u8  w, h    비트맵 크기
  u8  xo, yo  left bearing, ascent(baseline→top)
  u8  adv, pad
  u16 u, v    아틀라스 좌표(픽셀)
```
레코드가 UCS2 정렬이라 조회는 이진탐색 가능. default 원본 3,598글리프
(ASCII 95 + 가나 177 + CJK 2,988 + 전각 등).

## 한글 리베이크

가나·한자는 번역 후 게임 텍스트에 등장하지 않으므로 제거하고 그 자리를 한글로
재활용한다. 최종적으로 **"번역에 실제 쓰인 글자"만** 포함하도록 최적화했다.

- **유지**: ASCII·기호·전각 영숫자·그리스/키릴 등 + 번역에 실제 쓰인 원본 글자
  (중점 `・`, 로마숫자 `Ⅰ/Ⅱ`, 이름에 남은 한자 등은 원본 픽셀 그대로 복원)
- **한글**: 번역에 등장한 음절만 맑은 고딕 Bold로 렌더
- **세로 정렬**: yo는 글자별 실제 ascent(=baseline→top)를 쓰고, 대표 한글 top을
  원본 전각 yo(=17)에 맞춰 전체를 shift. 고정값을 쓰면 윗변 정렬이 되어 밑변이
  들쭉날쭉해진다.
- **전각 영숫자**(０-９Ａ-Ｚ)는 한글과 같은 Bold로 통일. 반각 ASCII 숫자는 HUD
  정렬 때문에 원본 유지.

결과: default 원본 3,598 → 1,386글리프, 아틀라스 352×4096 내, 폰트 용량은 원본보다
작아진다(한자 제거 효과).

## 별표(글리프 없음) 함정

폰트에 글리프가 없는 문자는 `*`(notdef)로 렌더된다. 겪은 사례:
- 중점 `・`(U+30FB, 가나 블록) 1,150회 — 가나 삭제 때 같이 지워짐
- 로마숫자 `Ⅰ`(U+2160) — 추출 필터에서 누락되어 미번역
- 반각 `·`(U+00B7), `®` — 번역가가 도입한, 폰트에 없는 기호

→ 번역에 쓰인 모든 문자를 수집(`build_used_chars.py`)해 폰트에 반드시 글리프를
보장하고, 폰트에 없는 반각 기호는 번역 후처리로 정규화(`postprocess_trans.py`).
