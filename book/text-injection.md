# 텍스트 삽입 기법

번역 대상은 고유 3,354개(용어 1,452 + 문장 1,902), 약 10만 자. 컨테이너별로 삽입
방식이 다르다. 구현: `csvb.py`, `dictbin.py`, `eboot_patch.py`, `apply_all.py`.

## CSVB 행 문자열 (자유 길이)

행의 `0x1B`(문자열 오프셋) 컬럼이 가리키는 UTF-8 문자열을 교체한다.

- **원본 풀은 보존**하고 번역문을 풀 끝에 append, 행의 오프셋만 새 위치로 갱신.
  (원본 오프셋을 그대로 두면 숨은 참조가 있어도 안전)
- 무변경 리빌드 = 바이트 동일 검증.
- 헤더의 `str_end`/`extra_off`를 새 풀 크기에 맞춰 갱신.

## ADV 대사 (mm01.advcmd, 임의 길이)

미션 대사는 행이 아니라 후행 `extra`(ADV 바이트코드) 섹션의 **u32 오프셋 필드**가
strbase 상대로 문자열을 가리킨다. 처음엔 "원문 길이 이내 제자리 교체"만 했더니
번역이 길어 15개가 skip → 원문(별표) 노출.

해결(`csvb.rebuild_advcmd`): 원문 풀 보존 + 번역 append 후, extra 섹션의 u32들을
스캔해 **유효한 대사 문자열 오프셋을 가리키는 값만** 새 위치로 repoint. 이로써
임의 길이 대사 삽입이 가능하다. 무변경=바이트 동일, 번역 185개 오프셋 갱신 확인.

## 사전 (제자리)

`dictbin.py`. 고정 슬롯(name 0x80 / text 0x1000)이 커서, 번역+널이 슬롯 이내면
제자리 교체로 충분(초과 0건).

## EBOOT UI

타이틀 메뉴·인스톨·난이도·옵션·조작·도감 라벨 등 UI 문자열은 CPK가 아니라
**EBOOT(SELF)** 안에 있다(고유 ~535개).

- RPCS3는 EBOOT 재서명이 불필요 → 복호화 ELF의 문자열을 **슬롯(원문 바이트) 이내
  제자리 교체**(`eboot_patch.py`). 크기·오프셋 불변.
- 한국어가 원문보다 1~2바이트 길어 skip되는 경우가 많다 → 공백 제거 + UI 용어
  정규화(`돌아가기→뒤로` 등)로 대부분 해결(`fix_eboot_length.py`).
- 추출 필터가 로마숫자 `Ⅰ`(U+2160) 등 특수문자를 놓쳐 미번역이 남을 수 있으니
  전수 재확인 필요.

## 검증

`validate_trans.py`로 삽입 전 제어코드(`\n`, `%d`, `@i(N)`, `[..]`, `<..>` 태그)의
보존 여부, 미번역·누락을 점검한다. 게임의 사전 링크 태그(`<용어>`)는 화면 표시
텍스트이므로 번역하되, 내부 참조 방식은 인게임에서 확인한다.
